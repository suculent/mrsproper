SCRIPT STRUCTURE (implement all of the following):

**Header comment block (replaces a separate README):**
Explain purpose, prerequisites (`.env` with `MRSPROPER_API_ID`/`MRSPROPER_API_HASH`, Node 20+, run from repo root), usage examples (including how to pass a saved StringSession via `--session <value>` to skip re-login), and a Q1–Q5 findings table the operator fills in manually.

**CJS interop for the `telegram` package:**
GramJS ships as CommonJS. Import it via `createRequire`:
```
import { createRequire } from 'module'
const require = createRequire(import.meta.url)
const { TelegramClient, StringSession, Api } = require('telegram')
```
Import `dotenv/config` first to load `.env` into `process.env`.

**CLI argument parsing (no external library):**
Parse `process.argv` for:
- `--group <@username|id>` — test group (required)
- `--user <@username|id>` — target member (required)
- `--tag <string>` — tag string to set (required; allow empty string for "clear" test)
- `--session <StringSession>` — saved session string (optional; avoids re-login)
- `--confirm` — skip the typed-"yes" gate (for scripted re-runs; still prints what it will do)

If any required arg is missing, print usage and exit 1.

**Interactive login:**
Read `MRSPROPER_API_ID` and `MRSPROPER_API_HASH` from `process.env`. Parse API_ID as integer.
Create `TelegramClient` with `floodSleepThreshold: 60`, `connectionRetries: 3`.
Call `client.start({ phoneNumber, phoneCode, password })` with `readline` prompts on stdin for each callback. After successful start, print:
```
[SESSION] StringSession to reuse on next run (--session flag):
<client.session.save()>
```
NEVER write the session string to any file. Print only to stdout.

**Entity resolution and Q5 probe:**
Resolve the group entity with `client.getEntity(groupArg)`. Print the raw entity constructor name (e.g. `Chat` vs `Channel`). If it is a `Chat` (basic group), print "Q5: CONFIRMED — basic group, editAdmin is channels-only; skipping write." and exit 0.

**Q2 pre-call participant snapshot:**
Resolve the target user entity with `client.getEntity(userArg)`. Print id + username + firstName from the resolved entity.
Call `client.getParticipants(groupEntity, { search: '' })` (or `iterParticipants`) and find the target. Wrap the result parse in try/catch; dump the raw participant object with `JSON.stringify(participant, null, 2)` (handles BigInt-safe printing via a replacer: `(_, v) => typeof v === 'bigint' ? v.toString() : v`). Label this "Q2 PRE-CALL participant state".

**Confirmation gate:**
Print exactly what the script is about to do:
```
ABOUT TO CALL: channels.EditAdmin
  group : <resolved group title + id>
  user  : <resolved user display name + id>
  rank  : "<tagString>"
  adminRights: ChatAdminRights{} (all flags false/omitted)
```
If `--confirm` flag is absent, prompt "Type 'yes' to proceed: " and read from stdin. Any other input → print "Aborted." and exit 0.

**The editAdmin call (Q1/Q2/Q3 probe):**
Build `InputChannel` and `InputPeerUser` using the same big-integer pattern as `RemovalExecutor`:
```
bigInt(entity.id.toString()), bigInt(entity.accessHash.toString())
```
Wrap the call in try/catch:
```
const result = await client.invoke(new Api.channels.EditAdmin({
  channel: inputChannel,
  userId: inputUser,
  adminRights: new Api.ChatAdminRights({}),
  rank: tagString,
}))
```
On success: print "[Q1/Q2] editAdmin succeeded. Raw result:" + JSON.stringify(result, bigIntReplacer, 2).
On error: print "[Q3] RPC error — errorMessage:", err.errorMessage, "\nFull error:", err.

**Q2 post-call participant snapshot:**
Repeat the `getParticipants` lookup and print the raw participant object. Label "Q2 POST-CALL participant state". The diff between pre and post is what the operator examines for Q2.

**Q4 guidance print:**
After the call completes (success or error), print:
```
[Q4] To test max-length/charset: re-run with --tag "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA" (33 chars)
     or --tag "" (empty) and observe the RPC error message above.
```

**Graceful disconnect:**
Call `client.disconnect()` before exiting.

ANTI-PATTERNS to avoid:
