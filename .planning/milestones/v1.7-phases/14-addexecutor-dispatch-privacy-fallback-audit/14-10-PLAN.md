<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> ADD_START payload | Only `dialogIds` is accepted; `resume` is computed server-side from `auditStore.readJob()` — the renderer cannot force or deny a continuation by lying about resume intent. |
| renderer -> ADD_RETRY_GROUP | dialogId cross-checked against the CURRENT job's dialogIds (not the live enumeration) — prevents retrying a group that was never part of this run. |
| main -> renderer (ADD_GET_JOB) | targetAccessHash is stripped before the job ever serializes across contextBridge. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-15 | Tampering | ADD_START dialogIds payload | mitigate | Dialog-map cross-check against `enumerator.getState().dialogs` (mirrors T-05-05-A/T-10-07) — renderer cannot inject an unenumerated group id. |
| T-14-16 | Elevation of Privilege | ADD_START resume flag | mitigate | `resume` is never read from the renderer payload — the Zod schema admits only `dialogIds`; the handler computes resume intent itself from the on-disk job, and `AddExecutor` independently re-validates targetId/dialogId-set equality (D-20) before actually continuing. |
| T-14-17 | Information Disclosure | ADD_GET_JOB response | mitigate | `targetAccessHash` destructured out before the object crosses IPC (T-10-01 pattern). |
| T-14-18 | Denial of Service | target:addContact failure | mitigate | Handler wraps `contactService.addIfMissing()` in try/catch; a rejection never propagates as an IPC error (D-08's non-blocking contract enforced at the boundary too, in case contactService itself is ever modified to throw). |
| T-14-SC | Tampering | npm/pip/cargo installs | accept | No new packages; zod/electron already dependencies. |
</threat_model>
