<objective>
Add the renderer-side state and dispatch logic for the "Add to contacts" checkbox (D-08/D-09/D-10). The main-process `target:addContact` handler already shipped in Phase 14 and is exposed on `window.mrsproper.addTargetToContacts()` by the existing preload — but no renderer TypeScript file declares that method on the `MrsProperApi` global interface yet, and no store wraps it. This plan adds both, plus the idempotent dispatch helper both Plan 15-11 (TargetCard) and Plan 15-10 (ReviewScreen run-confirm) will call.

Purpose: D-09's two possible trigger points (confirm-time if already in Add mode, run-confirm-time if Add mode was entered after confirming) must call the exact same underlying action so the "at most once per target" guarantee holds regardless of which fires first.

    - toggleAddToContacts(false) sets addToContactsChecked to false; toggleAddToContacts(true) sets it back to true; toggling never touches contactAddAttempted/contactAddFailed
    - maybeAddToContacts() when addToContactsChecked is false: does NOT call targetClient.addTargetToContacts(), does NOT set contactAddAttempted
    - maybeAddToContacts() when addToContactsChecked is true and contactAddAttempted is false: calls targetClient.addTargetToContacts() exactly once, sets contactAddAttempted to true
    - maybeAddToContacts() called a second time after a first successful dispatch (contactAddAttempted already true): does NOT call targetClient.addTargetToContacts() again (enforces "at most once per target")
    - maybeAddToContacts() when targetClient.addTargetToContacts() resolves { ok: false }: sets contactAddFailed to true, still sets contactAddAttempted to true, never throws
    - maybeAddToContacts() when targetClient.addTargetToContacts() rejects: caught, sets contactAddFailed to true, sets contactAddAttempted to true, never throws (never propagates to the caller)
    - resetTarget() clears addToContactsChecked back to true, contactAddAttempted back to false, contactAddFailed back to false (new target session starts fresh)
