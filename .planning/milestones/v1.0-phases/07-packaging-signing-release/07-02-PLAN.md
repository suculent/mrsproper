<objective>
Configure the build system for code-signed, notarized macOS output. Three changes across four files: (1) electron-builder.yml — remove the identity:null signing suppressor, remove zip targets (D-04), add hardened runtime / entitlements / comment block; (2) build/entitlements.mac.plist — new file with the three Electron-required hardened runtime exceptions; (3) .env.example — extend with four notarization credential variables and usage notes; (4) package.json — bump version to 0.9.0 RC (D-11) and add "release" script entry.

Purpose: electron-builder.yml's `identity: null` is a YAML null value (not a string) that calls handleNullIdentity() in macPackager.js and hard-skips signing regardless of env vars. Removing it lets electron-builder auto-detect the Developer ID Application cert from Keychain. The entitlements plist is mandatory for hardened-runtime notarization — V8 JIT and unsigned executable memory would be blocked without allow-jit and allow-unsigned-executable-memory. notarizeIfProvided triggers automatically when APPLE_API_KEY/APPLE_API_KEY_ID/APPLE_API_ISSUER are set; no custom afterSign hook is needed.

Output: Signing-ready electron-builder config, entitlements plist, extended .env.example, version bumped to 0.9.0.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| .env → electron-builder process | APPLE_API_KEY (path to .p8), APPLE_API_KEY_ID, APPLE_API_ISSUER flow from .env into electron-builder's child Node process via shell env export in the release script |
| Developer ID cert (Keychain) → codesign | electron-builder calls system codesign with the cert; the cert private key never leaves the Keychain |
| signed .app → Apple notarization server | xcrun notarytool uploads the signed app bundle to Apple's servers for validation |

| T-07-04 | Spoofing | Wrong certificate selected (Apple Development cert instead of Developer ID Application) | mitigate | identity: null removed; electron-builder auto-selects Developer ID Application type from Keychain.
