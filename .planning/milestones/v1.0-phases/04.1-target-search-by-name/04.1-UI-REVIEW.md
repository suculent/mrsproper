## Top 3 Priority Fixes

1. **Missing "Found in: " prefix on candidate rows** — Spec layout (§Candidate List) and Copywriting Contract both lock `"Found in: {group}, {group} +{N} more"`. `formatFoundIn()` (`searchCopy.ts:67-74`) returns only the joined titles, and `CandidateRow.tsx:142-148` renders it raw — the third line reads as an unlabeled group list with no context. **Fix:** prepend `Found in: ` inside `formatFoundIn` (keeps the string in the copy module).
2. **Hardcoded strings in components violate the copy-module contract** — Spec: "All strings live in `src/renderer/target/searchCopy.ts`. No hardcoded strings in components." Violations: `"Stop search"` label (`CandidateList.tsx:63`), `aria-label="Stop name search"` (`CandidateList.tsx:60`), `"Name"` chip label (`TargetInput.tsx:317`), `"Name search mode detected"` sr announcement (`TargetInput.tsx:337`), candidate-row aria-label template (`CandidateRow.tsx:108`). **Fix:** move all five into `SEARCH_COPY` (label + helper for the aria template).
3. **Terminal search errors render in the wrong slot, without the error treatment** — Spec Error States: "inline under the input, destructive text + AlertCircle, field stays editable." `CandidateList.tsx:137-141` renders a bare `text-destructive` paragraph below the (now-empty) list area, with no `AlertCircle`, and `TargetInput`'s error slot (`TargetInput.tsx:360-369`) never surfaces search errors. **Fix:** surface `search.step === 'error'` through TargetInput's existing inline error pattern (or replicate icon + placement in CandidateList).

### Pillar 2: Visual hierarchy (7/10)

**Passing:**
- Row is a native `<button>` with `min-h-[56px] px-4 py-3 flex items-center gap-3 w-full text-left hover:bg-accent/10` + focus-visible ring — character-for-character match to spec (`CandidateRow.tsx:100-110`).
- Name `text-label font-semibold text-foreground truncate` (`:132`), identity line mono + muted (`:137`), found-in muted (`:144`) — three-tier hierarchy as specified; ID never hidden (`:92-94`).
- Avatar 36px with colored-initials fallback, `AVATAR_COLORS[id % 7]`, white semibold, two-letter initials, duplicated per PATTERNS.md (`:16-65`) — matches contract and GroupRow precedent.
- Selecting spinner: `Loader2` 16px right-aligned, `aria-hidden`, sibling rows disabled (`:153-158`, `CandidateList.tsx:104`).
- Progress block: label + right-aligned ghost Stop search + `h-1` bar, `role="status" aria-live="polite"` (`CandidateList.tsx:51-74`) — mirrors Phase 4 scan pattern.
- Empty state: semibold label heading + muted body, input stays editable, no destructive styling (`CandidateList.tsx:125-134`).
- Render-nothing-when-idle contract honored (`CandidateList.tsx:27`), double-gated in `AppShell.tsx:40`.

**Deviations:**
- **Ghost icon 16px vs spec 24px** — spec: "lucide `Ghost` (24px …) matching TargetCard's deleted treatment"; TargetCard uses `h-6 w-6` (`TargetCard.tsx:112`), CandidateRow uses `h-4 w-4` (`CandidateRow.tsx:122`). WARNING.
- **Terminal error slot** — see priority fix #3. WARNING.
- **`role="list"` on a `<div>` whose children are `<button>`s with no `role="listitem"`** (`CandidateList.tsx:93-97`) — a list with zero list items to assistive tech. Spec offered `<ul>/<li>` OR `aria-label` on a plain container; the hybrid is worse than either. Minor WARNING — drop `role="list"` or add `listitem` wrappers.
- **Escape-to-stop not implemented** — Interaction Contract: "Escape while the scan runs triggers Stop search." No `Escape`/`keydown` handler exists anywhere in `src/renderer` (grep: zero hits). WARNING (interaction, folded here).

### Pillar 3: Color (10/10)

- Accent (`bg-primary`) appears exactly once in the new surfaces: the progress-bar fill (`CandidateList.tsx:68`) — on the enumerated reserved-for list. Find person button (existing) and focus rings (`ring-ring`, `CandidateRow.tsx:104`) are the only other accent uses, both pre-approved.
- Stop search: `variant="ghost" size="sm"` with `text-muted-foreground hover:text-foreground` (`CandidateList.tsx:56-64`) — explicitly NOT accent, as required.
- Name mode chip: muted, no fill, identical treatment to Username/Phone chips (`TargetInput.tsx:310`).
- Destructive used only for inline errors (`TargetInput.tsx:363`, `CandidateList.tsx:138`); FLOOD subline correctly carries no error styling.
- Row hover `bg-accent/10`, container `border`/`divide-border` — matches.
- `AVATAR_COLORS` hex literals (`CandidateRow.tsx:16-24`) are the sanctioned 7-hue palette (spec §Color, "duplicate again in CandidateRow, do not abstract"). No other hardcoded colors. No new colors introduced.

### Pillar 4: Typography (7/10)

- Sizes in new code: `text-label` and `text-body` only — within the 4-size scale; heading/display correctly unused. Weights: 400/600 via `font-semibold` — within the 2-weight scale.
- Mono correctly applied to the identity line `@{username} · ID {id}` (`CandidateRow.tsx:137`) and to the collapsed input summary — identity-strings-always-monospace rule honored.
- **DEVIATION — mono on prose:** the FLOOD subline renders the entire sentence in `font-mono` (`CandidateList.tsx:79`). The mono stack is reserved for `@username`, IDs, and countdowns; spec wanted a normal muted sentence accompanied by the monospace `FloodCountdown` component. WARNING.
- **DEVIATION — `FloodCountdown` missing:** spec: "…with the existing monospace `FloodCountdown` when `governorFloodRemaining > 0`." The subline shows no countdown at all (`CandidateList.tsx:78-82`), so the user can't see how long the pause lasts. WARNING.
- `text-xs` on avatar initials (`CandidateRow.tsx:117`) is a fifth size, but it is an exact duplicate of GroupRow (`GroupRow.tsx:124`) which the spec mandates mirroring — inherited deviation, informational only.

### Pillar 5: Spacing (8/10)

- Row: `min-h-[56px] px-4 py-3 gap-3` — exact match to the spec's own row contract (spec §Candidate row prescribes `gap-3` even though the token table says sm/8px; implementation follows the explicit row spec, which also matches GroupRow). PASS.
- Avatar `h-9 w-9` (36px) — exact (`CandidateRow.tsx:112`). PASS.
- `max-w-[560px]` on both TargetInput (`TargetInput.tsx:248`) and CandidateList (`CandidateList.tsx:48`). PASS.
- AppShell places CandidateList in TargetCard's slot with `mt-4` (16px = md) below the input block (`AppShell.tsx:38-43`). PASS.
- Cap notice `px-4 py-2` — exact (`CandidateList.tsx:112`). PASS.
- **DEVIATION:** CandidateList internal stack uses `space-y-3` (12px) (`CandidateList.tsx:48`) where the spec declares md/16px between progress indicator → candidate list; 12px is not a declared token (xs 4 / sm 8 / md 16). Minor WARNING — change to `space-y-4`.
- Empty state `py-8` (32px = xl) is on-scale but undeclared for this surface — informational.
