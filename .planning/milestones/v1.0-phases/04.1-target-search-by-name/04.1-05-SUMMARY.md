## Decisions Made

- `getLastQuery()` from searchStore: module-level ref captures the query at dispatch time; avoids prop-drilling for rare empty-state use. Ref is set before the async IPC call, so it's always available when CandidateList renders the empty state.
- `governorFloodRemaining` from `useTargetStore`: the FLOOD_WAIT subline in CandidateList reuses the same governor event source that drives TargetInput's flood countdown — no duplicate store wiring needed.
- `TargetCard` always mounts (React hooks compliance) but returns null when not in resolved/confirmed state — `CandidateList` renders null on idle. Both live in the same `mt-4` div in AppShell, rendering independently based on their state.
