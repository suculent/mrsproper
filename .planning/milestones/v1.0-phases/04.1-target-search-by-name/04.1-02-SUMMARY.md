# Phase 04.1 Plan 02: ParticipantSearcher + resolveByCandidate Summary

**One-liner:** Group-scoped participant name search service with streaming SearchState and CR-02 generation guards; TargetResolver extended with users.GetUsers candidate resolution path.

## What Was Built

### Task 1: ParticipantSearcher.ts + GREEN participantSearcher.test.ts

Created `src/main/telegram/ParticipantSearcher.ts` — the group-scoped name search service. Structure mirrors `MembershipScanner.ts` exactly:

- **Supergroup path:** `channels.GetParticipants` with `ChannelParticipantsSearch` filter (server-side, returns only matching users)
- **Basic-group path:** `messages.GetFullChat` + client-side token filter (tokenizes query, checks name+username)
- **Deduplication:** candidates accumulator map keyed by userId; `foundIn` array merged across groups
- **Streaming:** emits `{step:'searching', progress, candidates, errorCount}` after each group; final `{step:'complete'}` after all groups
- **Generation guard (CR-02):** double-check `gen !== this._generation || signal.aborted` before try AND after try/catch — stale results from superseded search never emit
- **abortSearch():** increments generation, aborts AbortController, clears `_candidateAccessHashes`, emits `{step:'idle'}`
- **Security (T-04.1-03):** `_candidateAccessHashes` is a private Map — accessHash never appears in any emitted `CandidateDTO`
- **Pitfall 9:** `ChannelParticipantsNotModified` className check → return [] without crash

Replaced all 7 `it.todo()` stubs in `participantSearcher.test.ts` with working implementations:
- TGT-05a: supergroup via GetParticipants — streams candidates, excludes accessHash from DTO
- TGT-05b: basic-group client-side filter — only matching users in output
- TGT-05c: userId deduplication + foundIn merging across 2 groups
- TGT-05d: generation guard — second search() cancels first before emitting complete
- TGT-05e: abortSearch() emits idle + clears getCandidateAccessHash()
- TGT-05f: per-group error (FLOOD_WAIT) increments errorCount, continues to next group
- TGT-05k: ChannelParticipantsNotModified returns gracefully, no crash

### Task 2: TargetResolver.resolveByCandidate() + GREEN targetResolver tests

Added `public async resolveByCandidate(userId: bigint, accessHash: bigint, username?: string): Promise<void>` to `TargetResolver.ts`.

Structure exactly mirrors `resolve()`:
- Claims new generation token → emits `{step:'resolving'}`
- Constructs `Api.InputUser({userId: bigInt(userId.toString()), accessHash: bigInt(accessHash.toString())})`
- Calls `users.GetUsers([inputUser])` via governor
- Username fallback: if GetUsers throws or returns empty AND username provided → falls back to existing `_resolveByUsername()` path (handles expired accessHash edge case)
- Generation guard before writing `_resolvedUserId`/`_resolvedAccessHash` and before emitting
- Falls through `_fetchBio`/`_fetchAvatar`/`_buildDTO` → emits identical `{step:'resolved'}` shape as username/phone paths

Added 4 new tests in `targetResolver.test.ts` under `describe('resolveByCandidate')`:
- TGT-05j (happy path): GetUsers → resolved state with correct id/name, no accessHash in DTO
- TGT-05j (transitions): resolving → resolved state machine
- TGT-05j (getResolvedUser): bigint id available after confirm()
- TGT-05i (generation guard regression): reset() during mid-flight GetUsers → final state is idle, no resolved emission
