<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
    Phase 6 complete wizard: five-stage step indicator (Target → Groups → Review → Run → Report), Review screen (SAF-01/02/03), severity selector persisted via electron-store, FLOOD_WAIT subline in Run stage, structured summary band with "Remove someone else" reset.
  </what-built>
  <how-to-verify>
    Launch the app (`npm run dev` or the built binary). Log in if not already authenticated.

    **Test 1: Step indicator visible**
    - Confirm a slim step indicator strip appears below the header with labels: "Target › Groups › Review › Run › Report"
    - "Target" should be bold/semibold; others muted. The strip is NOT clickable.

    **Test 2: Target stage → Groups stage transition**
    - Resolve a test target (username or phone). Confirm target by clicking "Yes, this is the person".
    - The step indicator should now show "Groups" as current.
    - GroupsPane should be in checklist mode and start scanning.

    **Test 3: Groups → Review navigation (run-trigger)**
    - Wait for the scan to complete. Check at least one group.
    - The run-trigger button should read "Review removal of {N} group{s}" in accent/primary (not red).
    - Click it. The wizard should navigate to the Review stage.
    - **No RemovalConfirmDialog should appear** (it was retired).

    **Test 4: Review screen content (SAF-01)**
    Confirm the Review screen shows:
    - [ ] Page heading: "Review removal"
    - [ ] Target avatar (or initials fallback) + full name + @username (if applicable) + "ID {numeric-id}" in monospace
    - [ ] "Action" label with "Kick" / "Ban" segmented control; default selection is "Kick"
    - [ ] Consequence line changes when toggling Kick ↔ Ban
    - [ ] Totals line: "Removing from {N} group{s}" (+ optional "· {M} excluded..." / "· {K} can't block rejoin")
    - [ ] Scrollable group list with each group's title, member count, and mechanic note
    - [ ] Basic-group ban rows show a warning icon + "Will be removed — rejoin can't be blocked in basic groups"
    - [ ] "Edit selection" button (outline, left) and "Kick/Ban {name} from {N} groups" button (destructive, right)

    **Test 5: Confirm gate is the ONLY gate (SAF-02)**
    - Click "Kick/Ban {name} from {N} groups" on the Review screen.
    - Execution should start immediately (wizard advances to Run stage).
    - **No second dialog should appear** after clicking the confirm button.

    **Test 6: Run stage progress**
    - Confirm per-group progress bar is visible during execution.
    - If possible to trigger a FLOOD_WAIT (or mock one): confirm the subline "Telegram asked us to slow down — resuming automatically." + countdown appears under the progress bar.
    - Per-row removal statuses update as groups complete.

    **Test 7: Report stage + "Remove someone else"**
    - After execution completes (or stops), wizard advances to Report stage.
    - Summary band shows "Removed {n} · Already gone {n}" etc. with bold counts and muted labels.
    - "Remove someone else" button is present.
    - Click "Remove someone else" — wizard should return to Target stage, all state cleared.

    **Test 8: Severity persistence**
    - Change severity to "Ban" in the Review screen.
    - Close the app and relaunch.
    - Navigate to the Review screen again — severity selector should default to "Ban" (persisted choice).

    **Test 9: Back navigation**
    - On the Review screen, click "Edit selection" — should return to the Groups stage (checklist visible).
    - On the Groups stage with a confirmed target, the existing "Change target" button should work.
    - During the Run stage (while execution is active), there should be NO back navigation affordances.
  </how-to-verify>
  <resume-signal>Type "approved" if all checks pass, or describe specific issues found (component, behavior, expected vs actual)</resume-signal>
