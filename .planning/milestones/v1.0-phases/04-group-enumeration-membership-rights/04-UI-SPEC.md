## Spacing Scale

Declared values (8-pt grid, multiples of 4 only). Established in globals.css Phase 1 and carried forward unchanged.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between badge and label |
| sm | 8px | Row internal padding, gap between group avatar and text |
| md | 16px | Pane padding, form element spacing |
| lg | 24px | Section gaps within a pane, gap-6 equivalents |
| xl | 32px | Major section breaks |
| 2xl | 48px | Reserved (not used in Phase 4 pane interior) |
| 3xl | 64px | Reserved (page-level; not used in Phase 4 pane interior) |

Exceptions:
- Left pane: `p-4` (16px) interior padding — matches RESEARCH.md AppShell code example
- Right pane: no interior padding on the outer container; GroupsPane manages its own padding (`p-4` for toolbar, no padding for the scroll list so rows can extend edge-to-edge)
- Group avatar thumbnail: 36px (9 Tailwind units, `h-9 w-9`) — a deliberate non-8pt value chosen for row density; not a spacing token

## Color

Tokens established in globals.css Phase 1. Phase 4 introduces no new colors. The two new semantic uses are enumerated in the accent reserved-for list.

| Role | Light value | Dark value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `#FFFFFF` (`--background`) | `#0B1220` (`--background`) | App background, right-pane scroll area surface, left-pane surface |
| Secondary (30%) | `#F1F5F9` (`--secondary`) | `#1E293B` (`--secondary`) | Header band (unchanged), left pane slight surface tint, groups pane toolbar row |
| Accent / Primary (10%) | `#2563EB` (`--primary`) | `#3B82F6` (`--primary`) | Checkbox fill when checked, refresh button (ghost hover), scan progress bar fill, filter input focus ring |
| Muted foreground | `#64748B` (`--muted-foreground`) | `#94A3B8` (`--muted-foreground`) | Grey-out reason subtext, member count, empty-state body, scan progress counter |
| Destructive | `#DC2626` (`--destructive`) | `#EF4444` (`--destructive`) | Per-row verify-failed state ("Couldn't verify") text tint; per-row retry affordance is NOT destructive — use ghost variant |
| Border | `#E2E8F0` (`--border`) | `#334155` (`--border`) | Vertical divider between left and right panes (`border-r border-border`), row separators (optional `divide-y divide-border`) |
| Success | `#16A34A` (`--success`) | `#22C55E` (`--success`) | Not used in Phase 4 (reserved for confirmed target indicator in Phase 3, carried from TargetCard) |

**Accent reserved for** (explicit list — Phase 4 additions bolded):

- Submit / primary action buttons (`bg-primary`)
- Focus rings (`ring-ring`)
- **Checkbox fill when a group row is checked** (`bg-primary` via Radix Checkbox indicator)
- **Scan progress bar fill** (`bg-primary` on the progress track)
- Resend link / text-link actions (`text-primary`)

Accent is NOT used for: greyed-out row backgrounds, type badge backgrounds (use `secondary`), row hover states (use `bg-accent/10` subtle hover), general informational text.

**Greyed-out row treatment:** non-actionable rows use `opacity-50` on the entire row content (avatar, name, reason, badge) with `cursor-not-allowed` on the checkbox wrapper. Do NOT use a different background color — keep the row background consistent; opacity alone signals non-actionability.

## GroupRow Visual Specification

### Actionable row

```
┌─────────────────────────────────────────────────────────────┐
│ [checkbox ✓]  [avatar 36px]  Group Name                     │
│                              1,234 members                  │
└─────────────────────────────────────────────────────────────┘
```

- Checkbox: `@radix-ui/react-checkbox`, filled with `bg-primary` when checked
- Avatar: 36px (`h-9 w-9`), `rounded-full`; initials fallback using group name first character, deterministic bg color from the 7-hue AVATAR_COLORS palette already in TargetCard
- Group name: `text-label` weight 600, `text-foreground`, truncated with `truncate` if overlong
- Member count: `text-label` weight 600, `text-muted-foreground` — formatted as compact number (see Copywriting Contract)
- Row hover: `hover:bg-accent/10` on the entire row (subtle)
- Row height: `min-h-[56px]` to accommodate two-line text (name + member count)
- Padding: `px-4 py-3`
- No type badge on actionable rows (D-04)

### Greyed (non-actionable) row

```
┌─────────────────────────────────────────────────────────────┐
│ [dimmed box]  [avatar 36px, opacity-50]  Group Name         │  opacity-50
│                              1,234 members                  │
│                              [Badge: Supergroup]            │
│                              You're not an admin here       │  text-muted-foreground
└─────────────────────────────────────────────────────────────┘
```

- Entire row content wrapped in `opacity-50`
- Checkbox area: non-interactive dimmed square (`cursor-not-allowed`), visually consistent size with actionable checkbox but no interaction
- Type badge: present on greyed rows only; variants map as:
  - `'basic-group'` → `<Badge variant="secondary">Group</Badge>`
  - `'supergroup'` → `<Badge variant="secondary">Supergroup</Badge>`
  - `'broadcast-channel'` → `<Badge variant="secondary">Channel</Badge>`
- Grey-out reason: `text-label text-muted-foreground` directly under member count — always visible, no hover required (D-03)

### Failed-verify row

```
┌─────────────────────────────────────────────────────────────┐
│ [dimmed box]  [avatar 36px, opacity-50]  Group Name         │  opacity-50
│                              1,234 members                  │
│                              Couldn't verify — [retry]      │  destructive text + ghost retry
└─────────────────────────────────────────────────────────────┘
```

- Reason text: `text-label text-destructive` for "Couldn't verify —" portion
- Retry affordance: inline `<button className="text-label text-primary underline-offset-2 hover:underline">retry</button>` (ghost link style, not a Button component — single word inline)
- Retry does NOT appear as a separate full-width button

### Scan-pending row (during scan, before result arrives)

- Row shows in browse-mode appearance (no checkbox, no reason) with a subtle pulsing skeleton on the checkbox area: `animate-pulse bg-muted rounded`
- This state is transient; once the governor check completes, the row transitions to actionable or greyed

## Progress Indicator Specification

Source: CONTEXT.md D-05, D-06.

The scan progress indicator lives in the GroupsPane toolbar area, above the group list.

**During scan:**
```
Scanning your groups...   checked 12 / 47   [progress bar]
```

- "Scanning your groups..." — `text-label text-muted-foreground`
- Counter "checked 12 / 47" — `text-label font-semibold text-foreground` (numbers bold, separators muted)
- Progress bar: full-width thin bar (`h-1`), `bg-muted` track, `bg-primary` fill animated with `transition-[width]`
- Bar width: `{checked}/{total} * 100%` (CSS width percentage)
- The checklist is interactive during scan — rows that have resolved are immediately toggleable (D-06)

**Scan complete:**
- Progress indicator removed; no persistent "complete" message
- If some rows failed: `N groups couldn't be verified. You can retry them above.` — `text-label text-muted-foreground` — shown below the toolbar

## Copywriting Contract

All strings live in `src/renderer/groups/groupsCopy.ts`. No hardcoded strings in components. (i18n hygiene per ROADMAP.md Phase 8 note.)

### Primary CTAs

| Element | Copy | Notes |
|---------|------|-------|
| Refresh button label | "Refresh" | In toolbar; icon-only with tooltip for small widths |
| Refresh button tooltip | "Re-fetch your group list from Telegram" | Always visible on hover |
| Retry link (per failed row) | "retry" | Lowercase, inline link style |

### Scan states

| State | Copy |
|-------|------|
| Scan in progress — label | "Scanning your groups…" |
| Scan in progress — counter | "checked {N} / {M}" |
| Scan complete, some failed | "{N} group{s} couldn't be verified. You can retry {them/it} above." |

### Grey-out reasons (inline subtext, always visible)

Exact strings per `GreyReason` value. These go into `groupsCopy.ts` as a `Record<GreyReason, string>`.

| GreyReason | Copy |
|------------|------|
| `not-creator` | "Only group creators can remove members here" |
| `no-ban-right` | "You don't have the ban right in this group" |
| `broadcast-channel` | "Channel — subscribers can't be removed" |
| `not-admin` | "You're not an admin here" |
| `verify-failed` | "Couldn't verify —" (followed by inline retry link) |

No Telegram jargon in these strings. No RPC error codes ("CHAT_ADMIN_REQUIRED" etc.) ever reach the user.

### Empty states

| Scenario | Heading | Body |
|----------|---------|------|
| Browse mode — no groups at all (admin has no groups) | "No groups found" | "Your Telegram account doesn't appear to administer any groups or channels." |
| Browse mode — filter returns no matches | "No matches" | "No groups match that filter. Try a different name." |
| Checklist mode — target is not in any group | "Not in any of your groups" | "{Name} isn't a member of any group you can remove them from. They may have already left, or you lack removal rights in all your groups." |

### Error states

| Scenario | Copy |
|----------|------|
| Group enumeration failed — FLOOD_WAIT | "Too many requests. The group list will load automatically when Telegram allows it." |
| Group enumeration failed — NETWORK | "Couldn't reach Telegram. Check your connection, then tap Refresh." |
| Group enumeration failed — UNKNOWN | "Something went wrong loading your groups. Tap Refresh to try again." |
| Scan failed entirely (hard stop, not per-row) | "The membership scan couldn't complete. Tap Refresh to restart." |

### Member count formatting

Format as compact locale string. Use `Intl.NumberFormat('en', { notation: 'compact' })` — outputs "1.2K", "47", "10K" etc. No full number display in rows (too wide for narrow group name area). Exact implementation in `groupsCopy.ts`:

```typescript
export function formatMemberCount(count: number | null): string {
  if (count === null) return ''
  if (count < 1000) return count.toString()
  return new Intl.NumberFormat('en', { notation: 'compact', maximumFractionDigits: 1 }).format(count)
}
```

## Interaction Contract

### Checkbox toggle (GRP-02, GRP-03)

- All actionable rows start pre-checked (default = remove from all groups)
- Unchecking a row marks it as "keep in this group" — visually the checkbox becomes unchecked, row remains actionable (same opacity, same style)
- No confirmation required for uncheck — it is a non-destructive preference change
- "Select all" / "Deselect all" controls: not in Phase 4 scope (deferred to Phase 6 review screen)

### Row ordering (D-01)

- Actionable rows rendered first; greyed rows grouped below
- Within each section: default sort is A–Z by group title
- Sort toggle: a small `<button>` in the toolbar — "A–Z" (active) toggles to "By size" — changes sort within actionable section and within greyed section independently
- Sort toggle: `text-label text-muted-foreground` with `hover:text-foreground` transition

### Target change (D-13)

When TargetCard's "Change target" is clicked:
1. GroupsPane returns to browse mode immediately
2. Checklist state (checked set, scan results) is cleared
3. Browse-mode filter input resets to empty
4. Scan progress indicator disappears

### Refresh (D-14)

- Manual refresh button in the groups pane toolbar (browse and checklist modes)
- On click: re-fetches dialog list from Telegram (governor-routed); pane shows loading state
- Loading state: replace group list with skeleton rows (3 placeholder rows, `animate-pulse bg-muted rounded`)
- Does NOT trigger a new membership scan — scan is only triggered by target confirmation

### Scroll behavior

- Right pane uses `@radix-ui/react-scroll-area` wrapping the group list
- List can be arbitrarily long; virtual scrolling is NOT required in Phase 4 (discretion: acceptable for typical admin group counts of <200; if performance issues arise in Phase 5+ testing, add react-virtual at that point)
- Toolbar (search + sort toggle + refresh + progress) is sticky at the top of GroupsPane, outside the ScrollArea

## Accessibility Contract

- All checkboxes: `<Checkbox>` from `@radix-ui/react-checkbox` with `aria-label="{groupName} — include in removal"` and `aria-checked` managed by Radix
- Greyed rows: the non-interactive checkbox wrapper has `aria-disabled="true"` and `role="checkbox"` with `aria-checked="false"` — announced as "unavailable" to screen readers
- Grey-out reason: rendered as visible text (D-03) so it is read naturally by screen readers without needing `aria-describedby`
- Scan progress: `role="status"` `aria-live="polite"` region wrapping the "checked N / M" counter — announced on updates
- Retry button per failed row: `aria-label="Retry membership check for {groupName}"`
- Sort toggle button: `aria-pressed="true/false"` reflecting current sort mode
- Refresh button: `aria-label="Refresh group list"` always (even when icon-only)
- Keyboard: Tab navigates checkboxes in row order; Space toggles checkbox; Enter on retry button triggers retry
