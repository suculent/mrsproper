<objective>
Fix three scan-lifecycle bugs (CR-01, CR-02, CR-03) that prevent Phase 4 truths 6, 7, and 8 from passing verification. All three share a single root cause: scan state was not wired to reset on target change, and the renderer store did not distinguish first-complete from retry-complete.

Purpose: The core product guarantee — "remove the right person from every relevant community" — requires that confirming target B always scans for target B. CR-01 breaks this guarantee. CR-02 can crash the app during a retry. CR-03 silently re-includes groups the admin explicitly excluded from the removal set.

Output: Four modified files (MembershipScanner.ts, targetChannels.ts, groupsStore.ts, GroupsPane.tsx) and an expanded test file with regression coverage for all three bugs.
</objective>
