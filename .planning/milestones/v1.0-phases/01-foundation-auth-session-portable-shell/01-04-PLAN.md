- RESEARCH Pattern 2 = authFlow.ts: do NOT use `client.start()`. `client.sendCode(apiCreds, phone)` returns `{ phoneCodeHash, isCodeViaApp }`; submit code via `client.invoke(new Api.auth.SignIn({ phoneNumber, phoneCodeHash, phoneCode }))`; catch `err.errorMessage === 'SESSION_PASSWORD_NEEDED'` (exact string — Pitfall 4) → branch to needPassword; `client.signInWithPassword(apiCreds, { password })` for 2FA (do NOT hand-roll SRP). `fetchIdentity` = `getMe()` + `downloadProfilePhoto(me)` (empty → null for initials fallback) per D-11.
- RESEARCH Pattern 4 = SessionManager owns one `TelegramClient(new StringSession(saved), API_ID, API_HASH, { connectionRetries:5, floodSleepThreshold: 5 })` — LOW threshold so login flood waits THROW and surface as a countdown (Pitfall 5 / D-13), not silently sleep. State machine: idle→sendingCode→needCode→(verifying)→[needPassword]→authorized | error | floodWait. Emit each new AuthState via an injected callback (wired to webContents.send in Task 2). error carries retryStep so the renderer stays on the offending step (D-12). On FLOOD_WAIT in submitCode/submitPassword, use FloodWaitController to emit flood ticks + a floodWait state.
- RESEARCH Pattern 6 = logout: `try { Api.auth.LogOut } catch { serverRevoked=false } finally { disconnect; wipeSession() }` — ALWAYS wipe (D-17). Return `{ serverRevoked }`.
- Restore on launch (RESEARCH Pattern 3 note + Code Examples): after app ready, `restoreSession()` → if string, connect + `checkAuthorization()`. If connect/auth throws `AUTH_KEY_UNREGISTERED`/`SESSION_REVOKED`/`AUTH_KEY_DUPLICATED` → `wipeSession()` + route to login with a brief notice (Claude's-discretion default in CONTEXT). On `safeStorage` unavailable → in-memory only, route to login.
- RESEARCH Pattern 1 = preload: `contextBridge.exposeInMainWorld('mrproper', { submitPhone, submitCode, submitPassword, resendCode, getAuthState, logout, onAuthState, onFloodTick })`. Each event subscriber returns an unsubscribe. - RESEARCH Security V5 = zod-validate EVERY inbound IPC payload in authChannels.ts before use (SubmitPhone/SubmitCode/SubmitPassword). Reject malformed payloads.
- Identity avatar crosses IPC as bytes (Uint8Array) or a data URL — never the session. The renderer renders it (plan 05).
- All of authFlow/SessionManager is plain Node/TS unit-tested with the plan-02 mocks — no Electron launch. The preload + main wiring is verified by the manual login checklist at the phase gate.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | renderer reads/exfiltrates the session string | mitigate | contextBridge whitelist only; preload never references session/client/API_HASH (automated grep guard, Task 2); handlers return serializable DTOs only |

| T-04-03 | Repudiation / Spoofing | logout leaves a live server-side authorization | mitigate | Api.auth.LogOut in try / wipeSession in finally always runs; serverRevoked:false surfaced to UI when revoke fails (Task 1, D-17, Pitfall 8) |
| T-04-04 | Information Disclosure | dead/leaked session reused after revocation | mitigate | restore() detects AUTH_KEY_UNREGISTERED → wipeSession + route to login (Task 1) |
| T-04-05 | Denial of Service | login FLOOD_WAIT silently slept → looks hung | mitigate | floodSleepThreshold:5 so waits throw → FloodWaitController countdown (Task 1, D-13/Pitfall 5) |
