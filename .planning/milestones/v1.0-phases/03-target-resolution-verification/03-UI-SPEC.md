# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase inherits the Phase 1 design system wholesale** (see `01-UI-SPEC.md`, status: approved — design-system genesis). Tokens below are restated for executor convenience, not re-decided. What is NEW in this phase: the smart target input with detected-mode indicator, the target identity card with confirm gate, the Telegram-style colored-initials avatar fallback, the keep-or-remove contact dialog, and cause-specific resolution error copy (TGT-04). This UI replaces the stubbed target-input region in `src/renderer/shell/StubbedWorkflowRegions.tsx`.

## Spacing Scale

Inherited 8-point scale (all multiples of 4), mapped to Tailwind defaults:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between badge icon and badge label; gap between AlertCircle and inline error text |
| sm | 8px | Gap between country chip and input field; gap between detected-mode chip and input edge; gap between badges on the identity card |
| md | 16px | Gap between input row → hint/error line → Find button; inner padding of the identity card's text stack |
| lg | 24px | Identity card inner padding; gap between avatar and identity text stack; gap between card body and the confirm-button row |
| xl | 32px | Gap between the section heading block and the input row; gap between input area and the rendered identity card |
| 2xl | 48px | Major break between the target-resolution section and the (still stubbed) group-list region below it |
| 3xl | 64px | Not used by this phase's surfaces (no full-page framing here) |

Exceptions:
- **64px avatar** on the target identity card (larger than the 48px shell identity — visual verification is the entire point of this card). 64 is on-grid.
- **44px minimum hit target** for icon-only controls (country chip trigger, dialog close) — Phase 1 constraint, still applies.
- **Content max-width 560px** for the target input row, hint lines, and the identity card, left-aligned inside the workflow region (the shell region itself stays full-width with its existing `p-6`).

## Typography

Inherited: Inter, exactly 4 sizes, exactly 2 weights (400 / 600). Utility classes already exist in `globals.css` (`.text-display`, `.text-heading`, `.text-body`, `.text-label`, `.text-mono`).

| Role | Size | Weight | Line Height | This phase's usage |
|------|------|--------|-------------|--------------------|
| Display | 28px | 600 | 1.2 | Not used in this phase (no full-screen step titles; this UI lives inside the shell) |
| Heading | 20px | 600 | 1.2 | Section heading "Who are you removing?"; target display name on the identity card; keep-or-remove dialog title; avatar fallback initials |
| Body | 16px | 400 | 1.5 | Section hint, bio text on the card, dialog body, no-photo notice body, input value text |
| Label | 14px | 600 | 1.5 | Field label, detected-mode chip text, inline errors, badges, `@username`, numeric ID, last-seen line, button labels, countdown, phone-mode disclosure hint |

Rules (inherited, restated):
- `@username`, numeric user ID, and phone numbers render in the **monospace stack** at their context's size.
- Never a 5th size or 3rd weight. Badges and chips use Label (14px/600) — do not invent a smaller "caption" size.
- Bio on the identity card clamps at 3 lines (`line-clamp-3`) with no expander in v1.

## Color

Inherited 60/30/10 contract. No new semantic colors for UI chrome. The only palette addition is the **avatar initials palette** — data-content color (like a profile photo), not UI chrome, and exempt from the 10% accent budget.

| Role | Value (light) | Usage |
|------|---------------|-------|
| Dominant (60%) | `#FFFFFF` | Workflow region background, input field, identity card surface |
| Secondary (30%) | `#F1F5F9` (slate-100) | Detected-mode chip fill, neutral Bot/Premium badge fill, no-photo notice background tint, country chip trigger |
| Accent (10%) | `#2563EB` (blue-600) | See reserved-for list |
| Destructive | `#DC2626` (red-600) | Inline resolution errors (text + field border), "Deleted account" badge (tinted: `text-destructive` on `bg-destructive/10` with `border-destructive/30`) |
| Success | `#16A34A` (green-600) | Confirmed-target check ONLY (extends Phase 1's confirmed-identity-only rule: green = "identity verified by the user") |
| Text muted | `#64748B` (slate-500) | Hints, detected-mode chip text, last-seen line, disclosure hint, "Change target" link |
| Border | `#E2E8F0` (slate-200) | Input border, identity card border, badge borders |

**Accent (blue) reserved for — explicit list (additions to the Phase 1 list):**
- The **Find person** button (the one primary action of the input state).
- The **"Yes, this is the person"** confirm button (the one primary action of the card state).
- The **"Remove contact"** primary button in the keep-or-remove dialog (cleanup is the recommended action; it is not destructive to the user's data the app didn't create).
- The focus ring on the active input (existing).
- The avatar ring on the **confirmed** target card (mirrors the logged-in identity ring — calm "this is locked in", not alarm).

**Explicitly NOT accent:** the detected-mode chip (muted/secondary — it informs, it must not compete with Find), the country chip, the "Change target" control (muted text link), badges.

**Avatar initials palette (D-12 — Telegram-style, deterministic):**
Keyed by `numericUserId % 7`, white (`#FFFFFF`) semibold initials on the fill:

| Index | Hex | Telegram peer color |
|-------|-----|---------------------|
| 0 | `#E17076` | red |
| 1 | `#FAA774` | orange |
| 2 | `#A695E7` | violet |
| 3 | `#7BC862` | green |
| 4 | `#6EC9CB` | cyan |
| 5 | `#65AADD` | blue |
| 6 | `#EE7AAE` | pink |

Same palette in dark mode (these hold contrast against white glyphs at 64px display size and are what Telegram admins already recognize). Initials = first letter of first + last name word, uppercased (reuse the `getInitials` logic from `IdentityDisplay.tsx`), Heading size (20px/600). Deleted accounts (no name) show a lucide `Ghost` icon at 24px in `muted-foreground` on a `secondary` fill instead of initials.

Plain, calm, trustworthy. No Telegram API jargon ever reaches the user (`USERNAME_NOT_OCCUPIED`, `FLOOD_WAIT`, `contacts.ImportContacts` are translated). All strings live in the renderer per the `errorCopy.ts` pattern — a new `resolveCopy.ts` (or extended copy module) is the canonical home.

| Identity card state | **Yes, this is the person** |

### Error states (TGT-04 / D-15 / D-16 — inline under the input, field stays editable, cause-specific + actionable hint)

| Trigger (typed code in `operationErrors.ts` extension) | User-facing copy |
|--------------------------------------------------------|------------------|
| Username not found (`USERNAME_NOT_OCCUPIED` → e.g. `TARGET_USERNAME_NOT_FOUND`) | "No one has the username @{handle}. Check the spelling — usernames can change or be deleted." |
| Username malformed (client-side, pre-send) | "That doesn't look like a valid username. Usernames have 5–32 letters, numbers, and underscores." |
| Phone not resolvable (import returned no user → `TARGET_PHONE_NOT_FOUND`) | "That number isn't on Telegram, or their privacy settings block phone lookup. If you know their @username, try that instead." |
| No public profile / unresolvable entity (`TARGET_NO_PUBLIC_PROFILE`) | "This person can't be looked up publicly. Telegram only allows lookup when their settings permit it — try their @username if you have it." |
| Invalid phone format (client-side, pre-send) | "That phone number doesn't look right. Check the country and number, then try again." |
| FLOOD_WAIT during lookup (D-17) | Find button disabled, label becomes "Try again in {mm:ss}" with live monospace countdown (FloodCountdown pattern, driven by governor `flood-tick` events on `OP_GOVERNOR_EVENT`). Inline line beneath: "Telegram asked us to slow down. The search will unlock automatically." |
| Network failure | "Couldn't reach Telegram. Check your connection and try again." |
| Unknown | "Something went wrong looking that up. Please try again." |

### Empty state

The input state IS the empty state of this region — section heading + hint + empty field (copy above). No separate placeholder panel. The group-list region below remains the Phase 1 stub ("Your groups will appear here once a target is selected." — already accurate; do not change it this phase).

### Destructive actions in this phase

**None.** Confirming a target performs no removal (the destructive gates are Phase 6). The keep-or-remove dialog deletes only a contact the app itself created seconds earlier — styled accent, not destructive red. Destructive red in this phase is reserved for inline errors and the "Deleted account" badge tint.

## Interaction Patterns

Inherited Phase 1 patterns referenced by name: **inline error**, **loading/disabled (spinner-on-button, 300ms min)**, **live countdown**, **confirm dialog**, **identity display**. New/extended patterns this phase establishes:

| Pattern | Contract |
|---------|----------|
| **Smart input mode detection (D-01/D-02/D-04/D-06)** | Single `Input`, full row width (max 560px). On each change: (1) trim; normalize pasted links — strip `https://`, `http://`, `t.me/`, leading `@`; `t.me/+<digits>` → phone with `+`. (2) Starts with `+` → phone (international; NO country chip). (3) Contains any letter or `_` → username. (4) All digits → phone with country chip (guess from system locale region — `navigator.language`/`Intl` region subtag, fallback to `DEFAULT_COUNTRY`; never IP-based, app must work offline). (5) Empty → no chip, Find disabled. The detected-mode chip renders inside the input's right edge (secondary fill, Label size, icon + word); it updates live as the user types and announces changes via `aria-live="polite"`. |
| **Country chip (D-02)** | Appears left of the input only in bare-digit phone mode. Reuses `CountryPicker` (flag + dial code trigger, searchable command list). Changing country never clears typed digits. Disappears when mode leaves bare-digit phone. |
| **Explicit Find (D-03)** | Resolution fires ONLY on Find click or Enter in the field. No debounce, no auto-lookup. While resolving: spinner-on-button (`Loader2` 16px, label stays "Find person"), input + chips disabled. Exactly one governor-routed call per attempt. |
| **Phone-mode disclosure (D-10)** | When phone mode is detected, the disclosure hint (copy above) renders as a muted Label-size line directly under the input, above any error line. It is informational — no modal, no blocking. |
| **Keep-or-remove dialog (D-07/D-08/D-09)** | Phase 1 confirm-dialog pattern (max-width 400px, Esc/overlay = Keep). Shown ONLY after successful phone resolution AND only when the app imported the contact this lookup. Failed lookups auto-clean silently (no dialog). Pre-existing contacts: no import, no dialog, ever. Dismissing the dialog (Esc/overlay/X) = Keep contact; the identity card is already rendered behind it either way. |
| **Target identity card (D-11/D-13/D-18)** | Bordered card (`rounded-lg border bg-card`, lg padding, max 560px), rendered below the input area on success. Layout: 64px avatar (left) + text stack: kicker "Is this the right person?" → name (Heading) with badges inline → `@username` (mono, muted) → "ID {id}" (mono, muted) → bio (Body, 3-line clamp) → last-seen line (Label, muted). Below the stack, md gap: no-photo notice (if applicable) and deleted-account supporting line (if applicable). Footer row (lg gap above): **Yes, this is the person** (accent) right-aligned, **Change target** (muted text button) left of it. |
| **Colored-initials fallback (D-12)** | `AvatarFallback` filled from the 7-color palette keyed by `id % 7`, white semibold initials at Heading size (20px/600). Always paired with the no-photo notice on the card — the colored circle alone is NOT sufficient disclosure. |
| **Confirm gate (D-11)** | Clicking "Yes, this is the person" locks the card: button row is replaced by the green `CheckCircle2` + "Target confirmed" affordance, avatar gains the accent ring, the input section above disables/collapses to a one-line summary, and downstream (Phase 4 region) unlocks. The confirmed target (numeric ID + access_hash, held in main) is the only thing later phases act on. |
| **Change target reset (D-14)** | Visible in both card states (pre- and post-confirm). Clicking it clears the card, the confirmed target, and ALL downstream state (group list), re-enables the input with its previous text selected for quick correction. No confirmation dialog in this phase (nothing destructive has happened yet); Phase 6 may add one once selections carry more weight. |
| **Lookup FLOOD_WAIT countdown (D-17)** | Reuses `FloodCountdown` (mm:ss, monospace, `tabular-nums`, `aria-live`). Find button disabled with "Try again in {mm:ss}"; auto re-enables at zero restoring "Find person". Timing source: governor `flood-tick` events over `OP_GOVERNOR_EVENT` — first operational consumer of the governor event stream. Input stays editable during the wait. |

**State machine for the region:** `idle → resolving → (error → idle-with-error) | resolved(card) → confirmed(locked)`; `Change target` from any card state → `idle`. Exactly one active target at a time.
