## Decisions Made
- `SEARCH_START` handler is declared `async` so Zod's synchronous throws are wrapped in rejected promises — this matches the `rejects.toThrow()` test pattern used throughout the codebase (groupChannels uses `async` for the same reason)
- `search()` call in handler is fire-and-forget (not awaited) — state arrives via `onStateChange → emitSearchState` push; handler returns the current snapshot from `getState()`
- `selectCandidate` returns `Promise<TargetState>` (not `Promise<unknown>`) since `TARGET_RESOLVE_CANDIDATE` calls `resolver.resolveByCandidate()` then returns `resolver.getState()` which is a `TargetState`

## Deviations from Plan

None — plan executed exactly as written.

The only minor adaptation: adding `async` to the SEARCH_START, SEARCH_ABORT, and SEARCH_GET_STATE handlers for consistent promise rejection behavior with Zod validation (matched the groupChannels.ts async pattern throughout).

## Issues Encountered
- SEARCH_START tests for `rejects.toThrow()` initially failed because the handler was declared synchronous — Zod throws synchronously but the test expects a rejected promise. Fixed by marking handler `async` (standard pattern for ipcMain handlers).
