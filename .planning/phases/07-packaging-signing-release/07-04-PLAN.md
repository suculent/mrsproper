<objective>
Run the release script to produce version 0.9.0 RC artifacts, then verify the signed macOS builds pass Gatekeeper assessment and stapler validation on the dev machine before distribution. This plan is a checkpoint: it automates as much verification as possible (spctl, stapler) but requires the human to confirm the signing log output during the build and the final artifact list.

Purpose: The script will attempt a live notarization call to Apple's servers (2-10 minutes). Build log output during notarization must show a successful notarytool submission, not a credentials error. If notarization fails, the cause (wrong APPLE_API_KEY path, expired key, wrong issuer ID) must be fixed before proceeding to clean-machine UAT.

Output: Signed, notarized macOS DMGs + unsigned Windows installers in release/dist/. Human-confirmed spctl acceptance and stapler ticket validation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dev machine → Apple notarization servers | xcrun notarytool uploads the signed .app bundle to Apple; Apple returns an acceptance ticket |
| release/dist/ → distribution (Drive/Telegram/USB) | Artifacts leave the dev machine; must be verified before handing off |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-11 | Tampering | Distributing an artifact that failed Gatekeeper validation | mitigate | spctl --assess and codesign --verify are run by the release script and rechecked manually in the checkpoint. Human must confirm "accepted" output before approving distribution. |
| T-07-12 | Disclosure | Apple receives the full .app bundle during notarization upload | accept | Apple's Developer ID notarization is the standard distribution path; Apple's privacy policy applies. The app binary contains the api_id/api_hash (known accepted risk per CLAUDE.md) — Apple's servers do not extract or publish it. |
| T-07-13 | Repudiation | Artifact is distributed before notarization is confirmed | mitigate | Checkpoint gate: human must confirm stapler validate success before release signal. Artifacts are in release/dist/ only after script confirms collection. |
| T-07-14 | Spoofing | Windows artifacts are unsigned — installer identity cannot be verified by SmartScreen | accept | D-05: Windows signing deferred. README (Plan 03) instructs users on "More info → Run anyway". Distribution is to known admins only (D-10). |
</threat_model>
