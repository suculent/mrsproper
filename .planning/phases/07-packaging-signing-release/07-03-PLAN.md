<objective>
Create two new files: the local release orchestration script (scripts/release.sh, D-09) and a user-facing README (D-08). The release script is the single entry point for every release: it validates prerequisites, runs type-check, builds, packages both platforms, performs Gatekeeper pre-verification on the dev machine, and collects artifacts into release/dist/. The README provides the only user-facing documentation needed: Windows SmartScreen "More info → Run anyway" steps and macOS minimum system requirement (macOS 11 Big Sur).

Purpose: Without the release script, the signing/notarization flow requires remembering to source .env, run tsc --build, run build, run package:mac, run package:win in the correct order — and a missed step causes a silent unsigned artifact or stale renderer. The script encodes the correct order with pre-flight validation that fails loudly on missing credentials. The README fulfills D-08 (SmartScreen instructions in release notes + README) so that admins receiving unsigned Windows builds know exactly what to click.

Output: scripts/release.sh (executable), README.md (user-facing, concise).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scripts/release.sh → .env | The release script sources .env and exports APPLE_API_KEY (path to .p8 key file) and notarization credentials into the child process environment |
| release script → npm run package:mac | Inherits APPLE_API_KEY/ID/ISSUER; electron-builder passes them to xcrun notarytool; credentials never written to disk by the script |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | Disclosure | .p8 key file path exposed in shell environment during release | accept | The key path is in process.env during the build; it is never echoed to stdout, not logged by electron-builder except as a redacted reference, and only accessible in the dev user's shell session. The key file itself lives outside the repo. Risk profile: local, short-lived. |
| T-07-08 | Disclosure | Notarization credentials in build logs | mitigate | electron-builder's MacTargetHelper redacts credentials in its log output (verified from source: env vars are read but not printed). Release script does not echo APPLE_API_KEY value. |
| T-07-09 | Spoofing | README instructions training users to bypass SmartScreen | accept | SmartScreen "More info → Run anyway" is the documented, Microsoft-supported path for unsigned apps from known publishers. This is the accepted v1 experience per D-05. Instructions include an honest explanation of why the warning appears. |
| T-07-10 | Disclosure | MRSPROPER_API_ID/HASH extractable from unsigned Windows binary | accept | Known, accepted risk documented in CLAUDE.md ("Shipping a single app-wide api_id/api_hash"). The pair is semi-public by design; mitigation is behavioral (rate-limit compliance) not technical for v1. |
| T-07-SC | Tampering | slopcheck — no new packages installed in this plan | accept | scripts/release.sh and README.md are plain text files; no npm install involved. No slopcheck checkpoint required. |
</threat_model>
