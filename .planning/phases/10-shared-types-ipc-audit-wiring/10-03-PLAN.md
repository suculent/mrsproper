<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main (TAG_START) | Renderer sends { dialogIds, tag }; main process adds identity from resolver — renderer can never inject target identity |
| enumerator state → payload validation | Only dialogIds present in the current enumeration are accepted; stale or forged IDs are rejected |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-06 | Elevation of Privilege | TAG_START payload (T-05-04-B) | mitigate | TagStartSchema admits only dialogIds + tag; executor.execute receives only those fields; identity sourced from resolver.getResolvedUser() in main (Phase 11) |
| T-10-07 | Tampering | dialogIds in TAG_START payload | mitigate | Dialog-map gate: throws Error if any dialogId not in enumerator.getState().dialogs (T-05-05-A pattern) |
| T-10-08 | Authentication Bypass | TAG_START while unauthorized | mitigate | Auth gate: getAuthState().step must equal 'authorized'; returns idle state otherwise |
| T-10-09 | Denial of Service | Double TAG_START (race) | mitigate | Double-start guard: step 'running' or 'stopping' returns current state without re-dispatching |
| T-10-10 | Denial of Service | Destroyed BrowserWindow push | mitigate | emitTagState checks win.isDestroyed() before webContents.send; test case 9 asserts this |
</threat_model>
