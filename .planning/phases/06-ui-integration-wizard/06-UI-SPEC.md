# Phase 6 — UI Design Contract

> Visual and interaction contract for UI Integration — Wizard, Safety Gates & Progress (SAF-01, SAF-02, SAF-03). Generated by gsd-ui-researcher (autonomous mode — all questions answered by upstream artifacts).
>
> **This phase inherits the Phase 1 design system wholesale** (restated in the approved 03/04/04.1/05 UI-SPECs). Tokens below are restated for executor convenience, not re-decided.
>
> **Scope:** (1) a slim five-stage step indicator over the existing two-pane flow (Target → Groups → Review → Run → Report), (2) the **Review screen** — the phase's main new surface: dry-run preview + identity block + severity segmented control + the single explicit destructive confirmation (replaces `RemovalConfirmDialog` in the start-run flow), (3) the Run stage framing of the existing Phase 5 progress slot **including the now-mandatory FLOOD_WAIT subline**, (4) the Report stage with "Remove someone else", and (5) absorption of the Phase 5 UI-audit advisories. **No new Telegram calls; the dry-run is pure local computation.**

Inherited 60/30/10 contract. **No new colors.** New semantic uses enumerated below.

| Accent (10%) | `#2563EB` (`--primary`) | `#3B82F6` | See reserved-for list |
| Success | `#16A34A` (`--success`) | `#22C55E` | Removal-success check icons only (inherited row states — unchanged) |
| Destructive | `#DC2626` (`--destructive`) | `#EF4444` | **Review confirm button** (the single gate), Resume removal buttons, failed-row treatment, PEER_FLOOD banner (all inherited) |
| Muted foreground | `#64748B` | `#94A3B8` | Step-indicator non-current stages, mechanic notes, member counts, warnings, FLOOD_WAIT subline, totals-line labels |
| Border | `#E2E8F0` | `#334155` | Step-indicator strip bottom border, group-list row separators, segmented-control border |

**Accent reserved for** (Phase 6 additions bolded):
- Submit / primary action buttons (non-destructive only)
- Focus rings
- Checkbox fill when checked
- Removal/scan/search progress bar fill (`bg-primary` on the `h-1` track)
- "retry" / "retry removal" inline links
- **Run-trigger button in its new role ("Review removal of {N} group{s}") — it now navigates to the Review stage and executes nothing, so it moves from destructive to accent primary (`variant="default"`)**
- **Severity segmented control: the selected segment (`variant="default"`)**

**Explicitly NOT accent:** the Review confirm button (destructive — it is THE gate), the step indicator current stage (foreground + semibold, not accent — it is orientation, not action), warnings (muted, never amber/red — a ban-fallback warning is information, not an error), "Edit selection" / "Remove someone else" (outline/ghost, muted).

**Destructive discipline:** destructive red appears on exactly one NEW element — the Review confirm button. Everything else red is inherited Phase 5 (failed rows, PEER_FLOOD banner, Resume removal). The dry-run preview itself contains no red: predicted outcomes are statements of plan, not failures.

## Layout Contract

### Stage → layout mapping

The wizard is a presentation layer over the existing shell. The step indicator is a new slim strip directly below the header, visible in all authenticated stages.

| Stage | Layout below the step indicator |
|-------|--------------------------------|
| `target` | Existing two-pane (left: TargetInput/CandidateList/TargetCard; right: GroupsPane browse mode) — unchanged |
| `groups` | Existing two-pane (right: GroupsPane checklist mode + scan) — run-trigger now navigates to Review instead of opening a dialog |
| `review` | **Full-width ReviewScreen** replacing both panes (max-width container `max-w-2xl mx-auto` for readable line lengths, `px-4 pt-8`) |
| `run` | Existing two-pane; GroupsPane progress slot owns the live progress (+ FLOOD_WAIT subline); TargetCard locked ("Stop the removal first" — inherited) |
| `report` | Existing two-pane; GroupsPane slot shows the summary band; "Remove someone else" appears with it (see Report stage spec) |

### Step indicator strip

```
┌──────────────────────────────────────────────────────────────┐
│ header band (unchanged)                                       │
├──────────────────────────────────────────────────────────────┤
│ Target › Groups › Review › Run › Report                       │  px-4 py-2, border-b
├──────────────────────────────────────────────────────────────┤
│ stage content (two-pane or ReviewScreen)                      │
```

- Strip: `px-4 py-2 border-b border-border bg-background shrink-0`, horizontal flex `gap-1 items-center`.
- Stage labels: `text-label`. Current stage: `text-foreground font-semibold` + `aria-current="step"`. Completed stages: `text-muted-foreground`. Future stages: `text-muted-foreground/60`.
- Separators: lucide `ChevronRight` `h-3 w-3 text-muted-foreground/60` `aria-hidden`.
- **Not clickable.** Navigation happens via explicit buttons (Change target / Edit selection / confirm / Remove someone else) — the locked back-navigation decision. The indicator is pure orientation.
- Wrapper: `<nav aria-label={wizardCopy.stepIndicatorAria}>` with an `<ol>` of stages.

### ReviewScreen layout (the new surface)

```
┌────────────────────────── max-w-2xl mx-auto ──────────────────────────┐
│ Review removal                                          text-heading  │
│                                                                       │
│ (avatar 36px)  Anna Nováková                       identity block     │
│                @anovak · ID 12345678               .text-mono, muted  │
│                                                                       │
│ Action   [ Kick | Ban ]                            segmented control  │
│ They'll be removed from all 12 selected groups,    text-body, muted   │
│ but they can rejoin later.                                            │
│                                                                       │
│ Removing from 12 groups · 2 excluded (no removal   totals line        │
│ rights) · 1 can't block rejoin                                        │
│ ┌─────────────────────────────────────────────┐                       │
│ │ Group A                1,204 members        │  ScrollArea           │
│ │ Will be removed — can rejoin later          │  (max-h, border,      │
│ ├─────────────────────────────────────────────┤   rounded-md)         │
│ │ Group B                  87 members         │                       │
│ │ ⚠ Will be removed — rejoin can't be         │                       │
│ │   blocked in basic groups                   │                       │
│ └─────────────────────────────────────────────┘                       │
│                                                                       │
│ [Edit selection]                  [Kick Anna Nováková from 12 groups] │
└───────────────────────────────────────────────────────────────────────┘
```

- Vertical rhythm: `flex flex-col gap-6` between major sections; `gap-4` within sections.
- Identity block: 36px avatar (`h-9 w-9`, initials fallback, `AVATAR_COLORS[id % 7]`, duplicated per PATTERNS.md), name `text-label font-semibold`, identity line `@{username} · ID {id}` in `.text-mono text-label text-muted-foreground`. **Numeric ID always shown** (SAF-01 / TGT-03 anchor). No-username targets show `ID {id}` only.
- Severity segmented control: two adjacent Buttons in a `flex rounded-md border border-border overflow-hidden` wrapper; selected segment `variant="default"`, unselected `variant="ghost"`, both `size="sm" className="rounded-none flex-1"`, inner divider `border-l border-border`. Below it, the consequence line for the CURRENT selection (`removalCopy.severityLine`) in `text-body text-muted-foreground`. Default **kick**; last choice rehydrated from electron-store via IPC; every change writes through.
- Totals line (`text-body`): counts `font-semibold text-foreground`, labels and `·` separators `text-muted-foreground`. Zero-count categories omitted (Phase 5 precedent).
- Group list: ScrollArea (`max-h-[40vh] border border-border rounded-md`), rows `px-4 py-2 border-b border-border last:border-b-0 flex flex-col gap-1`. Row line 1: title `text-label font-semibold text-foreground truncate` + right-aligned member count `text-label text-muted-foreground shrink-0` ("{n} members", n ≥ 1 always — these are groups). Row line 2: mechanic note `text-label text-muted-foreground`; ban-fallback rows prefix lucide `AlertTriangle h-4 w-4 text-muted-foreground shrink-0 aria-hidden` with `gap-1`. **Only checked + actionable groups appear** — excluded no-rights groups are represented by the totals-line count, not rows (they are not part of the run).
- Footer: `flex justify-between items-center`. Left: `<Button variant="outline">` "Edit selection". Right: `<Button variant="destructive">` — the single explicit confirmation. While dispatching: `Loader2 h-4 w-4 animate-spin` + "Starting…", both buttons disabled. **No dialog follows — this button IS the gate (SAF-02).**
- The severity selector and group list re-derive live: severity change recomputes every mechanic note, the warning rows, the totals line, and the confirm-button label in place (pure local computation — SAF-03, zero IPC).

### Dry-run mechanic derivation (locked semantics, user-facing rendering)

| Group type | Severity | Internal mechanic | User-facing mechanic note |
|-----------|----------|-------------------|---------------------------|
| supergroup / channel | ban | `editBanned` | "Will be banned — can't rejoin until you unban them" |
| supergroup / channel | kick | restrict-then-unban | "Will be removed — can rejoin later" |
| basic group | kick | `deleteChatUser` | "Will be removed — can rejoin later" |
| basic group | ban | `deleteChatUser` (ban fallback) | "Will be removed — rejoin can't be blocked in basic groups" + warning icon |

No Telegram jargon or RPC/method names ever reach the user. Group type comes from `AdminDialogDTO.type` (groupsStore), never from scan results (Phase 5 research pitfall 4).

### Run stage

The existing GroupsPane progress slot renders unchanged, with one addition now mandatory:

- **FLOOD_WAIT subline (Phase 5 Pillar 2 blocker — in scope):** when `removal.step === 'running'` and `removal.floodWaitRemaining > 0`, render under the progress label: `removalCopy.floodWaitSubline` ("Telegram asked us to slow down — resuming automatically.") in `text-label text-muted-foreground`, followed by the existing monospace `FloodCountdown remaining={...}` with `gap-1`. Bar holds its width. No error styling. Scoped to removal flood events only (RemovalState plumbing, NOT the shared OP_GOVERNOR_EVENT channel — pitfall 6).
- Stop removal, PEER_FLOOD banner, per-row statuses: inherited Phase 5 contract verbatim — no changes.
- Step indicator shows Run as current; all back navigation locked (no Change target, no Edit selection — inherited TargetCard lock + run-trigger absence).

### Report stage

- The GroupsPane summary band (inherited) is the report body. The summary counts line is **restructured** (Phase 5 Pillar 3 advisory, in scope): `removalCopy.summaryLine` returns `Array<{label: string; count: number}>`; GroupsPane composes spans — counts `font-semibold text-foreground`, labels and `·` separators `text-muted-foreground`. Visual outcome matches the original Phase 5 contract intent.
- **"Remove someone else"**: `<Button variant="outline" size="sm">` rendered with the summary band (right-aligned on the counts row, same pattern as Stop removal's placement on the progress row). On click: `TARGET_RESET` IPC → stage `target` with removal state cleanly idle. Per-row outcomes and retry links stay live until then (inherited).
- Resume flow: `ResumeJobDialog` unchanged; resuming jumps the wizard directly to the Run stage.

## Interaction Contract

| Pattern | Contract |
|---------|----------|
| **Stage machine** | `wizardStage` is explicit local state in AppShell — never fully derived from stores (prevents snap-back, pitfall 2). Transitions: target→groups on target confirm; groups→review on run-trigger click; review→run on confirm dispatch success; run→report on `removal.step ∈ {complete, stopped, hard-stopped}`; report→target on "Remove someone else" (after TARGET_RESET resolves). Resume: ResumeJobDialog "Resume removal" → stage run directly |
| **Back navigation** | Every stage can go back until execution starts: groups→target via Change target (inherited), review→groups via Edit selection. Locked from run onward: no back affordances during running/stopping; Report offers only "Remove someone else" (forward reset). Step indicator is never a navigation control |
| **Single gate** | Exactly ONE confirmation exists: the Review confirm button. `RemovalConfirmDialog` is removed from GroupsPane in the same change that adds ReviewScreen (atomic — pitfall 3). The Review screen is a UI gate; all main-process security gates on REMOVAL_START (Zod + auth + dialog-map + double-start guard) remain the security boundary |
| **Severity persistence** | Selector reads the persisted value on mount (IPC get, default kick); every toggle writes through (IPC set, Zod `z.enum(['kick','ban'])` in main). The selection drives: consequence line, mechanic notes, warnings, totals, confirm label — all recomputed live, zero IPC |
| **Dry-run recompute** | Planned actions derive from `groupsStore.groups` (AdminDialogDTO.type/.canAct) × `checkedDialogIds` × severity. Greyed/no-rights groups are excluded from rows and counted in the totals line |
| **Stale-click guard** | Confirm button disables immediately on click (dispatching state); the existing REMOVAL_START double-start guard backstops a stale second dispatch |
| **FLOOD_WAIT display** | Removal-scoped only: RemovalExecutor emits `floodWaitRemaining` on RemovalState; removalStore does NOT subscribe to OP_GOVERNOR_EVENT (pitfall 6). Render only when running AND remaining > 0; reset to null when the wait ends |
| **Run lock** | Inherited Phase 5 contract verbatim: checkboxes disabled, refresh disabled with tooltip, TargetCard "Stop the removal first", sort toggle visual-only |
| **Keyboard** | ReviewScreen: normal document flow (no focus trap — it is a stage, not a modal). Tab order: severity segments → group list (scrollable region focusable) → Edit selection → confirm. **No autofocus on the destructive confirm** — focus lands at the top of the Review content on stage entry (deliberate friction for a destructive gate). Esc does nothing on Review (no modal to dismiss; Edit selection is the explicit back). ResumeJobDialog keeps its Phase 5 explicit-button-only posture |

## Accessibility Contract

All aria strings live in copy modules (`wizardCopy.ts` / `removalCopy.ts`) — Phase 5 advisory absorbed.

- Step indicator: `<nav aria-label="Removal steps">` wrapping an `<ol>`; current stage `aria-current="step"`; chevrons `aria-hidden="true"`
- Review screen: `<section aria-labelledby>` pointing at the "Review removal" heading; on stage entry, focus moves to the heading (`tabIndex={-1}` + programmatic focus) so screen readers announce the stage change
- Severity segmented control: `role="radiogroup"` with `aria-label="Removal action"`; segments `role="radio"` + `aria-checked`; arrow keys move selection (standard radiogroup semantics on the Button pair)
- Group list: `<ul aria-label="Groups the target will be removed from">`; warning icons `aria-hidden` (the mechanic-note text carries the meaning as visible text)
- Confirm button: `aria-label` = visible label (already a full sentence: "Ban {name} from {N} group{s}") with correct pluralization via the `s(n)` helper — **fixes the Phase 5 "1 groups" aria plural bug class everywhere it appears**
- Totals line + summary band: plain visible text inside `role="status"` regions (announced once on render)
- FLOOD_WAIT subline: rendered inside the existing `role="status" aria-live="polite"` progress wrapper — announced as it appears
- Run-trigger: `aria-label="Review removal of {N} group{s}"` (matches visible label, pluralized)
- "Remove someone else": visible text is self-describing; no extra aria needed
