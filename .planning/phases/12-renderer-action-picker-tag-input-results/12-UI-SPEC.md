# Phase 12 — UI Design Contract

> Visual and interaction contract for the Tag action UI: action picker extension, tag input,
> tag confirmation, live progress, and per-group results report.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **IMPORTANT:** This phase extends a mature shipped design system (Phases 6 + 8).
> Every token, component, and pattern below is DETECTED from globals.css / tailwind.config.ts
> / existing components. Do NOT introduce new tokens or primitives. All new surfaces must
> look identical to their removal analogs unless explicitly differentiated here.

(`rounded-full px-2 py-0.5 text-mono text-label text-foreground`) so it reads as a literal value,
not body copy. This is an inline chip — not a Badge component — to avoid badge semantic confusion.

## Surface Specifications

### S-1: Action Picker (3-way segmented control)

**Location:** `ReviewScreen`, between the heading and the consequence block (replaces the 2-way control).

**Layout:**
```
[  Kick  |  Ban  |  Tag  ]
```

- Three `<Button role="radio">` segments inside a `role="radiogroup"` `<div>`
- Exact same `div` structure as today: `flex rounded-md border border-border overflow-hidden`
- Each button: `rounded-none flex-1`; left and middle buttons add `border-r border-border` to their right edge
- Active segment: `variant="default"` (primary fill); inactive: `variant="ghost"`
- `aria-checked={action === 'kick' | 'ban' | 'tag'}` on each button

**State rules:**
- Switching to "Tag" reveals the TagInput block (below the picker) via a `flex flex-col gap-2` wrapper
- Switching away from "Tag" hides TagInput and clears the tag value (no stale carry-over)
- The consequence line below the picker changes based on the active action (see S-2b)

**Labels:** see Copywriting Contract — keys `actionTag`, `actionKick`, `actionBan`

---

### S-2: TagInput Block

**Location:** Conditionally rendered below the action picker when action=Tag. Inside a `flex flex-col gap-2` wrapper.

**Visual layout (top to bottom):**

1. Section label: `<span class="text-label font-semibold">{t('tagInputLabel')}</span>`
2. `<Input>` with the tag value, `maxLength={TAG_MAX_LENGTH}`, `placeholder` per copy contract
3. Counter + validation row: `flex items-baseline justify-between`
   - Left: inline validation error when invalid (see below), or empty when valid
   - Right: character counter `{value.length} / {TAG_MAX_LENGTH}` in `.text-label text-muted-foreground`
4. Consequence line: `.text-body text-muted-foreground min-h-[2.5rem]` (same min-h as removal consequence, prevents layout shift) — shows the tag action description

**Input states:**

| State | Border / ring | Counter color | Error display |
|-------|--------------|---------------|---------------|
| Empty (pristine) | `border-input` (default) | `text-muted-foreground` | none |
| Typing, valid | `border-input` | `text-muted-foreground` | none |
| Too long (> TAG_MAX_LENGTH) | `border-destructive ring-destructive` | `text-destructive` | inline error below input |
| Contains control char / newline | `border-destructive ring-destructive` | `text-destructive` | inline error below input |
| Disabled (run in progress) | `disabled:opacity-50 disabled:cursor-not-allowed` | muted | none |

**Inline validation error:** `<p role="alert" class="text-label text-destructive">{errorMessage}</p>` — rendered in the left slot of the counter row. `role="alert"` so screen readers announce it immediately on type.

**`TAG_MAX_LENGTH` constant:** 16 (provisional, per CONTEXT.md). Defined once in
`src/shared/tagConstants.ts` (or equivalent). Both the input's `maxLength` HTML attribute AND the
validation function read from this constant.

**Charset validation rule:** reject if `value !== value.replace(/[\x00-\x1F\x7F\r\n]+/g, '')`.
Trimmed value must be non-empty before confirm button is enabled.

### S-3: Tag Confirmation Block in ReviewScreen

When action=Tag and confirm is clicked (or conceptually, the confirmation is shown inline — the
existing ReviewScreen IS the confirmation screen per the locked decisions), the following layout
applies:

**Section order (top to bottom):**
1. `<h2>` heading — `{t('tagReviewTitle')}` — `.text-heading font-semibold`
2. Identity block — identical to existing removal identity block (Avatar + name + @username + ID)
3. Tag string block — new:
   ```
   <div class="flex flex-col gap-1">
     <span class="text-label font-semibold">{t('tagLabel')}</span>
     <span class="bg-secondary rounded-full px-2 py-0.5 text-mono text-label text-foreground w-fit">
       {tagValue}
     </span>
   </div>
   ```
4. Action picker (3-way) — same as S-1
5. TagInput block (S-2) — visible because action=Tag
6. Totals line — `{t('tagTotalsTagging', { count: actionableCount })}` when count > 0; `{t('totalsEmpty')}` from wizard namespace when 0
7. Group list (ScrollArea) — identical to removal group list; each row shows group title + member count + a mechanic note `t('tag:mechanicNote.supergroup')` or skipped label for basic groups
8. Footer: Back button (outline) + Confirm button (`variant="default"`) — disabled when tag empty/invalid or count=0

**Mechanic notes in group list rows:**
- Supergroup/channel: `t('tag:mechanicNote.supergroup')` → "Will be tagged — member tag set across all admins"
  Wait — tag is set ON the member, not "across admins". Use: "Tag will be set"
- Basic group: `t('tag:mechanicNote.basicGroup')` → "Basic group — will be skipped"

Note on `variant="default"` vs `variant="destructive"`:
The tag confirm button uses `variant="default"` (primary blue). Tagging is not irreversible in the
same way as banning; it differs semantically from kick/ban. This is a deliberate visual
differentiation.

### S-4: Tag Run — Live Progress

**Integration point:** `GroupsPane` renders the progress slot based on which action's store is
active. When the active action is Tag, the progress slot reads from `tagStore` instead of
`removalStore`.

**Progress slot layout (mirrors removal S-4 pattern exactly):**

```
<div class="px-4 py-2 shrink-0" role="status" aria-live="polite">
  <div class="flex items-center justify-between mb-1">
    <span class="text-label text-muted-foreground">
      {t('tag:progressLabel', { name, x: processed + 1, n: total })}
    </span>
    <Button variant="ghost" size="sm" ...>{t('tag:stopLabel')}</Button>
  </div>
  <div class="h-1 bg-muted rounded-full overflow-hidden">
    <div class="h-full bg-primary transition-[width] duration-200" style={{ width: `${pct}%` }} />
  </div>
  {/* FLOOD_WAIT countdown — same pattern as removal */}
  {floodWaitRemaining != null && floodWaitRemaining > 0 && (
    <span class="text-label text-muted-foreground flex items-baseline gap-1">
      {t('tag:floodWaitSubline')}
      <FloodCountdown remaining={floodWaitRemaining} />
    </span>
  )}
</div>
```

**PEER_FLOOD hard-stop banner (tag):** mirrors removal `hard-stopped` Alert exactly:
- `<Alert variant="destructive" class="bg-destructive/10 border-destructive/30">` with `AlertTriangle` icon
- Body: `{t('tag:peerFloodBanner')}`
- Resume button: `variant="destructive" size="sm"` → `{t('tag:peerFloodResumeLabel')}`

### S-5: Tag Results — Per-Group Report

The results view renders in the same `GroupsPane` scroll list, with each row's "tag status" in the
checkbox slot and subline, mirroring removal row status.

**Tag status in checkbox slot:**

| tagStatus | Icon | Color |
|-----------|------|-------|
| `'tagging'` | `<Loader2 class="animate-spin">` | `text-muted-foreground` |
| `'done'` | `<Check>` | `text-success` |
| `'skipped'` | `<Minus>` | `text-muted-foreground` |
| `'failed'` | `<AlertCircle>` | `text-destructive` |
| `'queued'` | `<Checkbox checked disabled>` | — |

**Subline copy by outcome:**

| Outcome | errorCode | Subline copy key | Display |
|---------|-----------|-----------------|---------|
| `done` | — | `tag:rowStatus.done` | "Tagged" |
| `skipped` | `TAG_TARGET_IS_ADMIN` | `tag:rowStatus.skippedAdmin` | "Skipped — already an admin" |
| `skipped` | `TAG_UNSUPPORTED_BASIC_GROUP` | `tag:rowStatus.skippedBasicGroup` | "Skipped — basic groups not supported" |
| `skipped` | other | `tag:rowStatus.skipped` | "Skipped — tagging stopped" |
| `failed` | any | `tag:rowError.{errorCode}` | error-specific copy + no retry button |
| `tagging` | — | `tag:rowStatus.tagging` | "Tagging…" |

Note: tag run has NO per-group retry (the IPC contract has no `retryTagGroup`). Failed rows show
the error copy but omit the retry button. This differs from removal.

**Summary band (complete or stopped):**

```
<div class="px-4 py-2 shrink-0 border-t border-border flex items-center justify-between gap-2 flex-wrap">
  <div class="flex flex-col gap-1">
    {step === 'stopped' && <span class="text-label text-muted-foreground">{t('tag:summaryStopped', {x, n})}</span>}
    [summary parts: tagged · skipped · failed — same dot-join pattern as removal]
    {completedAt && <span class="text-label text-muted-foreground">{t('tag:finishedAt', {time})}</span>}
  </div>
  <Button variant="outline" size="sm" onClick={reset}>{t('wizard:tagSomeoneElse')}</Button>
</div>
```

**Hard-stopped run distinction:** when `step === 'hard-stopped'` the PEER_FLOOD Alert (S-4) is
shown in the progress slot instead of the summary band. The Alert persists through the `report`
stage until the user resumes or navigates away.

## Interaction State Machine

### ReviewScreen action picker

```
action: 'kick' | 'ban' | 'tag'     (lifted to AppShell state)
tagValue: string                     (local state in ReviewScreen / TagInput)
tagError: string | null              (derived, not stored)

Transitions:
  action changes to non-tag → tagValue = '', tagError = null
  tagValue changes → revalidate → derive tagError
  confirm pressed (action=tag) → disabled if tagValue.trim()==='' or tagError!==null or actionableCount===0
```

### AppShell active action routing

```
activeAction: 'kick' | 'ban' | 'tag'   (replaces severity-only state)

run stage:
  activeAction=tag → subscribe useTagStore, render tag progress slot
  activeAction=kick|ban → subscribe useRemovalStore (unchanged)

report stage:
  activeAction=tag → render tag results (tag summary band or PEER_FLOOD)
  activeAction=kick|ban → render removal results (unchanged)

auto-advance run→report:
  tag: tag.step === 'complete' | 'stopped' | 'hard-stopped' → setStage('report')
  removal: unchanged
```

### Segmented control a11y

- `role="radiogroup"` on the container `div`
- `aria-label={t('actionGroupAria')}` on the container
- Each `<Button role="radio" aria-checked={action === value}>`
- When Tag is selected and TagInput is mounted, focus the input automatically (`useEffect` + `ref.current?.focus()`)
