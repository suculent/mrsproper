## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Spoofing | TargetCard — identity confirmation | mitigate | Two explicit user gates: "Yes, this is the person" (Phase 3) and final review with numeric ID (Phase 6); card always shows the stable numeric ID (target.id) in monospace; tooltip explains it is the permanent ID MrProper acts on |
| T-03-13 | Information Disclosure | target.id displayed in UI | accept | Numeric Telegram user ID is low-sensitivity display data; the identity card exists specifically to let the admin verify this is the right person; displaying it is the safety property, not a leak |
| T-03-14 | Tampering | Link normalization in TargetInput | mitigate | Normalization runs client-side before dispatch; TargetResolver still receives the string through the IPC Zod validator (z.string().min(1)); malformed normalizations produce a TargetErrorCode error response, not a crash |
| T-03-15 | Information Disclosure | bytesToDataUrl — avatar bytes | accept | Avatar bytes are fetched from Telegram in main, passed as Uint8Array via IPC, converted to data: URL in renderer; data: URLs are allowed by the production CSP (img-src 'self' data:); no cross-origin exposure |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new npm packages in this plan; badge added in Plan 02 |
