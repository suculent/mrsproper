    - src/renderer/ipc/targetClient.ts — current broken file; the Window['mrproper'] & {...} self-referential intersection on line 12 is rejected by TypeScript because the base mrproper property is a plain object literal type, not an interface
  </read_first>

  <action>
    Apply approach (A) from the checker: introduce a named interface MrProperApi in authClient.ts so targetClient.ts can augment it via standard TypeScript interface merging. This is the canonical pattern — interface merging applies to named interfaces, not to inline property types.

    Step 1 — Edit src/renderer/ipc/authClient.ts. Change the declare global block so that instead of declaring mrproper as an inline object literal type, it declares a named interface MrProperApi containing the 8 auth methods, then declares Window.mrproper as type MrProperApi. The imports (AuthState, FloodTick, LogoutResult) and the exported authClient object body are unchanged.

    The revised declare global block in authClient.ts must be:

      declare global {
        interface MrProperApi {
          submitPhone(p: { dialCode: string; national: string }): Promise<AuthState>
          submitCode(p: { code: string }): Promise<AuthState>
          submitPassword(p: { password: string }): Promise<AuthState>
          resendCode(): Promise<AuthState>
          getAuthState(): Promise<AuthState>
          logout(): Promise<LogoutResult>
          onAuthState(cb: (s: AuthState) => void): () => void
          onFloodTick(cb: (t: FloodTick) => void): () => void
        }
        interface Window {
          mrproper: MrProperApi
        }
      }

    Step 2 — Edit src/renderer/ipc/targetClient.ts. Replace the entire declare global block (the broken Window['mrproper'] & {...} intersection) with an augmentation of MrProperApi. Do not re-declare Window.mrproper — augmenting MrProperApi is sufficient because Window.mrproper is already typed as MrProperApi in authClient.ts, and TypeScript's interface merging will automatically add the target methods to the same interface.

    The revised declare global block in targetClient.ts must be:

      declare global {
        interface MrProperApi {
          resolveTarget(input: string): Promise<TargetState>
          confirmTarget(): Promise<TargetState>
          resetTarget(): Promise<TargetState>
          getTargetState(): Promise<TargetState>
          onTargetState(cb: (s: TargetState) => void): () => void
          onGovernorEvent(cb: (e: GovernorEvent) => void): () => void
        }
      }

    No import for AuthState/FloodTick/LogoutResult is needed in targetClient.ts because those types are not referenced in its declare global block. The existing imports (TargetState, GovernorEvent) remain. The exported targetClient object body is unchanged — window.mrproper.resolveTarget(input) etc. remain valid because the merged MrProperApi now includes all 14 methods.

    After both edits, run the verify command immediately. Do NOT re-read either file first.
