  <action>
    Replace the Window interface augmentation in targetClient.ts. The current approach uses Window['mrproper'] & {...} — a self-referential intersection that TypeScript rejects (TS2717) because authClient.ts declares mrproper as a plain object type, not an interface.

    The fix is to use additive interface augmentation: declare a separate named interface (MrProperTargetMethods) containing only the 6 target methods, then declare a second interface Window block that intersects mrproper with that interface using a fresh augmentation pattern consistent with how TypeScript module augmentation works.

    Specifically: change the declare global block so Window.mrproper is declared using an intersection that does NOT reference Window['mrproper'] (remove the self-reference). Instead, redeclare mrproper as the exact union of both method sets in-line, OR use a named helper interface. The approach that works reliably in TypeScript strict mode with two ambient declarations is to use two separate interface declarations that TypeScript merges automatically via interface merging semantics.

    Concrete approach: In targetClient.ts, change the declare global block to:

      declare global {
        interface MrProperTargetMethods {
          resolveTarget(input: string): Promise<TargetState>
          confirmTarget(): Promise<TargetState>
          resetTarget(): Promise<TargetState>
          getTargetState(): Promise<TargetState>
          onTargetState(cb: (s: TargetState) => void): () => void
          onGovernorEvent(cb: (e: GovernorEvent) => void): () => void
        }
        interface Window {
          mrproper: Window['mrproper'] extends object
            ? Window['mrproper'] & MrProperTargetMethods
            : MrProperTargetMethods
        }
      }

    Wait — that still self-references. The correct minimal fix that TypeScript accepts when the base is a non-interface property (plain object literal type): declare mrproper as type intersection in a NEW interface that re-declares only the additional methods, using interface merging.

    The pattern that works: In authClient.ts, mrproper is a concrete object type, not an interface. TypeScript's interface merging does not apply to property types. The reliable fix is to change targetClient.ts so the augmentation adds mrproper as a fresh full type (copying the authClient.ts methods plus adding the new ones). However, this creates a maintenance burden.

    Preferred alternative: change authClient.ts to declare mrproper as an interface (named MrProperApi), then targetClient.ts augments MrProperApi. This is the canonical TypeScript pattern for this scenario. BUT — this changes authClient.ts which is Phase 1 code.

    Simplest fix that requires only changing targetClient.ts: declare the mrproper property with its full merged type inline (auth methods + target methods combined) in targetClient.ts, using `declare global { interface Window { mrproper: { ...auth methods... } & { ...target methods... } } }`. TypeScript allows re-declaring a property in an ambient interface augmentation IF the new type is assignable. Since the intersection of both sets is assignable to either, this works.

    Concretely — replace the entire declare global block in targetClient.ts with:

      import type { AuthState, FloodTick, LogoutResult } from '@shared/authTypes'

      declare global {
        interface Window {
          mrproper: {
            // Auth methods (from authClient.ts — kept here for intersection completeness)
            submitPhone(p: { dialCode: string; national: string }): Promise<AuthState>
            submitCode(p: { code: string }): Promise<AuthState>
            submitPassword(p: { password: string }): Promise<AuthState>
            resendCode(): Promise<AuthState>
            getAuthState(): Promise<AuthState>
            logout(): Promise<LogoutResult>
            onAuthState(cb: (s: AuthState) => void): () => void
            onFloodTick(cb: (t: FloodTick) => void): () => void
            // Target methods (Phase 3)
            resolveTarget(input: string): Promise<TargetState>
            confirmTarget(): Promise<TargetState>
            resetTarget(): Promise<TargetState>
            getTargetState(): Promise<TargetState>
            onTargetState(cb: (s: TargetState) => void): () => void
            onGovernorEvent(cb: (e: GovernorEvent) => void): () => void
          }
        }
      }

    This unified declaration matches the exact runtime shape of contextBridge.exposeInMainWorld('mrproper', {...}) in preload/index.ts (verified to contain all 14 methods). TypeScript merges this with the authClient.ts declaration because both augment the same ambient interface Window — the merged type has both sets of methods. The TS2717 error fires when the two declarations have DIFFERENT shapes; making both declare the complete shape resolves it.

    Add a comment above the auth method block: "// Auth methods (declared in authClient.ts — repeated here so TypeScript's interface augmentation merges correctly; see T-03-IPC note in STATE.md)". Do NOT add fenced code blocks in action — the above is directive prose.
