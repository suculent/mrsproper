<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| renderer → ADD_EXPORT_LOG | renderer requests an export; main alone chooses the source file and (via native dialog) the destination |
| renderer → CLIPBOARD_WRITE_TEXT | renderer sends arbitrary text (actually only ever a main-sourced invite link) to be written to the OS clipboard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Tampering | clipboardChannels.ts CLIPBOARD_WRITE_TEXT | mitigate | `z.object({ text: z.string().max(2000) })` bounds payload size; only caller is the Copy button next to a server-issued link |
| T-15-02 | Tampering | addChannels.ts ADD_EXPORT_LOG | mitigate | Source path always comes from `addLogStore.getLogPath()` (fixed, main-computed); destination path always comes from the OS-native `dialog.showSaveDialog` return value — renderer supplies neither |
| T-15-03 | Elevation of Privilege | clipboardChannels.ts, addChannels.ts ADD_EXPORT_LOG | mitigate | Both handlers gated on `getAuthState().step === 'authorized'`, consistent with every other handler in addChannels.ts |
| T-15-11 | Information Disclosure | addChannels.ts ADD_EXPORT_LOG | accept | The export is an intentional, user-initiated copy of already-0o600 add-log.txt to a user-chosen location outside userData — this is the feature's whole purpose, not a leak |
</threat_model>
