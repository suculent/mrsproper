<objective>
Close two related UAT gaps from Test 4 (15-UAT.md), both rooted in GroupRow.tsx rendering the "greyed" visual treatment (wrapper opacity, type badge, grey-reason caption) from the Remove-only dialog.canAct/dialog.greyReason fields with no activeMode gate, while the checkbox already correctly uses the mode-aware isActionableForMode. In Add mode this makes an actionable, pre-checked row (e.g. a supergroup where the admin can invite but not ban) render dimmed with the wrong caption, so the user cannot tell it is selected and does not uncheck it before a run.

Purpose: ADD-05 requires that in Add mode, actionable rows are visibly checked/interactive and non-actionable rows are greyed with the correct Add-specific reason. Both diagnosed debug sessions (add-mode-acts-on-unchecked-group.md, add-mode-shows-remove-grey-reason.md) land on the same fix in the same file.
Output: GroupRow.tsx renders a mode-correct grey treatment; groupsStore.ts's latent first-scan-complete hardcoded-mode bug is fixed alongside it (same root-cause family: mode not threaded through); a new GroupRow.test.tsx guards both behaviors and proves Remove/Tag output is unchanged.
</objective>
