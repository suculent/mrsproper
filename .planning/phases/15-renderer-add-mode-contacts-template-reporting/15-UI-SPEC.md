| Accent (10%) — `primary` | `#2563EB` blue-600 | `#3B82F6` blue-500 | See reserved-for list below |
| Destructive | `#DC2626` red-600 | `#EF4444` red-500 | See reserved-for list below |
| Success | `#16A34A` green-600 | `#22C55E` green-500 | "Added" / "Already a member" checkmarks (reuses the exact same `text-success` token as Removal's "Removed"/Tag's "Tagged" checkmarks — **no new success usage pattern**) |

**Accent reserved for** (explicit list — this phase adds exactly these elements to the existing
reserved-for set; nothing else may use `primary`):
- The active segment in the Remove/Tag/Add mode switch (`variant="default"` Button, matching the
  existing severity-picker active-segment pattern)
- The "Add" run-trigger button, the Add review screen's "Add {name} to N groups" confirm button
  (see Destructive note below), and the "Export add log…" button
- Progress-bar fill during an add run (reuses the exact `bg-primary` progress-bar pattern already
  shipped for Removal/Tag scan progress)
- Focus rings (`ring-ring`, same token as `primary`) on the mode switch, checkbox, textarea,
  Copy button, Save button
- Inline text links: "Edit template" toggle, "retry" links on failed add rows, "Copy" link/button
  on privacy-blocked rows (`text-primary underline-offset-2 hover:underline`, identical to the
  existing `retryRemovalAria`/`retryScanLabel` link styling)
- The pre-checked "Add to contacts" checkbox's checked-fill state (`data-[state=checked]:bg-primary`,
  the existing shadcn Checkbox default — no override)

**Destructive reserved for** (unchanged list; Add mode does **not** add new destructive usage):
- PEER_FLOOD banner (`Alert variant="destructive"`), unchanged copy pattern per group
- The "Discard job" action inside `AddResumeJobDialog` keeps its *button variant* as `outline`
  (non-destructive position, matching `TagResumeJobDialog`'s `variant="outline"` for discard) —
  discard is a neutral action, not styled destructive, consistent with Tag's precedent (D-21
  mirrors `TagResumeJobDialog` exactly)
- **[AUTO] Add's confirm button is `variant="default"`, NOT `variant="destructive"`.** Removal's
  confirm button uses `destructive` because kick/ban is destructive; Tag's confirm button already
  uses `default` because tagging isn't destructive (`ReviewScreen.tsx` line 416:
  `variant={action === 'tag' ? 'default' : 'destructive'}`). Adding someone to groups is the least
  destructive of the three actions — extend that same ternary to
  `action === 'remove' ? 'destructive' : 'default'` so both Tag and Add confirm buttons stay
  `default`/accent-colored, never red.
