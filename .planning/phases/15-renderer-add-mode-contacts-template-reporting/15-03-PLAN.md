<objective>
Introduce the two genuinely new pieces of pure logic this phase needs: (1) `isActionableForMode()` — the single shared predicate deciding, per mode, whether a checklist row is actionable and pre-checked, consumed by both `groupsStore.ts`'s pre-check rebuild and `GroupsPane.tsx`'s partition loop (Plan 15-09) so the two never silently drift apart; and (2) `computeAddGroups()`/`validateDmTemplate()` — the Add-mode siblings of `computeTagGroups`/`validateTagInput`, consumed by `ReviewScreen.tsx`/`DmTemplateEditor.tsx` (Plan 15-10).

Purpose: per 15-RESEARCH.md Pitfall 2/3, today's actionability rule and pre-check rebuild are hard-coded independently in two files with no `mode` parameter at all — this plan creates the one shared rule before any UI consumes it, and wires `groupsStore.ts`'s existing rebuild through it so Remove/Tag behavior is provably unchanged.
Output: `src/renderer/groups/modeRules.ts` (new), `src/renderer/store/groupsStore.ts` (modified — new `recomputeCheckedForMode` action, existing rebuild now calls the shared predicate), `src/renderer/wizard/addValidation.ts` (new), `src/renderer/wizard/wizardStage.ts` (modified — ADD_COMPLETE/ADD_STOPPED events, D-04).
</objective>
