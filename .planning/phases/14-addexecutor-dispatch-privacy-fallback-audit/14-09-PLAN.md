<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| add-job.json (disk) -> continuation decision | A resumed run trusts the on-disk job only after validating targetId AND dialogId-set equality (D-20) — an attacker who could write to userData could at most trigger a fresh job (safe fallback), never silently splice a different target's outcomes into a new run. |
| DM send -> SendMessage | The rendered DM text is built entirely from main-held data (template + target name + server-issued links) — no renderer-supplied content crosses into the message body. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-13 | Tampering | add-job.json continuation match | mitigate | D-20's equality rule (targetId AND dialogId-set, both required) rejects a mismatched on-disk job and falls back to a fresh run rather than silently continuing the wrong lineage. |
| T-14-14 | Information Disclosure | end-of-run DM contains single-use invite links | accept | The DM is sent only to the resolved target themselves (the intended recipient of those links) via the account's own governed SendMessage call — this is the feature's intended data flow, not a leak. |
| T-14-SC | Tampering | npm/pip/cargo installs | accept | No new packages; node:crypto is a Node builtin. |
</threat_model>
